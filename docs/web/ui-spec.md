# React Web 规范

## 1. 页面（共 16 个视图）

- 核心监控：系统总览（含管理员「立即全局健康检测」按需触发入口）、CPU（含过热降频计数）、GPU、主板传感器、内存、存储健康 / SMART（含持久化分区容量进度条、硬盘规格/APM/自检摘要与三语 SMART 属性释义）、NVMe、温度历史（含安全 CSV/JSON 导出）、风扇与电压、网络接口（物理网卡速率与错包/丢包）。
- 分析与管理：告警中心（含一键应用推荐安全规则）、健康评分与分析详情、硬件设备列表、传感器覆盖率、采集器诊断、系统配置（含 Webhook 配置与测试）、登录与首次初始化管理员。

## 2. UI、主题与国际化规则

- **多背景主题**：内置 6 套深色/浅色背景主题（`slate` / `obsidian` / `forest` / `amethyst` / `snow` / `warm`），基于 CSS 自定义属性实现，登录页与顶栏一键切换，持久化至 `localStorage` 并自动联动 ECharts 图表配色与 `color-scheme`。
- **三语国际化**：支持 `中文` / `English` / `日本語` 实时切换，同时本地化诊断日志、Haskell 评分依据与常见 SMART 属性说明。
- 统一加载、空数据、错误、权限不足状态与全局红/橙色告警横幅。
- 统一时间格式（展示本地时区，数据为 UTC）；数值必须带单位（物理网卡 `byte_per_second` 自动换算为 `Mbps (MB/s)`）。
- `unsupported`、`permission_denied`、`unavailable`、`standby` 必须有明确的可区分展示，并说明原因。
- **缺失数据（`null`）不得渲染为 0**，图表中强制 `connectNulls = false` 显示为断点而非连线。
- 历史图表必须支持时间范围选择（`15m` / `1h` / `6h` / `24h` / `7d`）。
- WebSocket 断开时显示连接状态，并标记数据可能不是最新。
- 不得在前端计算整机健康状态或评分；只展示 API 返回的 Haskell 分析结果。

## 3. 数据获取

- 实时数据通过 WebSocket 增量推送；历史数据通过 REST 查询。
- 禁止定时重新加载全部历史数据。
- 长时间范围使用 API 提供的聚合数据，前端只做必要的展示级降采样。
- 图表使用 ECharts。
